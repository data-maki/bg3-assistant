## 2026-07-13 — User-controlled overlay position persistence

- **Hypothesis:** The controller is recomputing its middle-right default during a later show/resize/window-sync path because it cannot reliably distinguish a migrated/default anchor from a user-authored drag; persisting explicit user intent alongside the normalized anchor and consulting it before default placement will preserve repositioning while retaining the correct first-run position.

- **Reflection:** Global mouse state is the wrong proxy for user intent in a deferred window notification. Compare the resulting frame with the controller-owned programmatic target, then keep normalized geometry responsible for translating the player's anchor across sizes and displays. The non-activating overlay is not exposed as a draggable window to the desktop automation bridge, so the packaged user-visible drag/relaunch gesture remains the final experiential check rather than being represented as automated evidence.
